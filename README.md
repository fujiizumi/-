# ホテル レベニューマネジメント AI

競合ホテルの価格、近隣イベント、天候、景気動向、地域の需要状況などを分析し、
**RevPAR（販売可能な客室1室あたり収益 = ADR × 稼働率）が最大になる価格**を
部屋タイプ・宿泊プランごとに日別で自動算出するダッシュボードです。全94室の
在庫を前提にしています。

## ホテル業務 AI活用マップ（`/ai-use-cases`）

ホテル経営の業務のうち、AIで効率化できるものを8部門・29業務に整理したページです。
各業務について「現状の課題」「AIでの効率化」「期待効果（目安）」「効果・導入難易度」
「必要なデータ・導入手段・注意点」を掲載し、部門・難易度・キーワードで絞り込めます。
導入ロードマップ（STEP1〜3）も掲載しています。掲載内容は `src/data/aiUseCases.ts` で編集できます。

## 使い方

```bash
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開くと、部屋タイプ・プラン・表示日数を選び、
日別の推奨価格・稼働予測・RevPARを確認できます。各行をクリックすると、
「なぜこの価格が合理的か」という根拠の説明文と、要因ごとの内訳
（競合価格、イベント、天候、景気、地域需要、価格感度）が展開されます。
ページ上部には、94室全体を対象にした期間平均RevPARと、基準価格で固定販売した
場合との収益比較（ホテル全体のRevPAR改善率）も表示されます。

## 構成

- `src/data/hotel.ts` — 部屋タイプ（合計94室）・プランのマスタデータ（実際のホテル情報に置き換えてください）
- `src/lib/signals.ts` — 外部要因シグナルの取得（**現在はデモ用の疑似データ**）
- `src/lib/pricingEngine.ts` — 需要曲線を推定し、RevPARを最大化する価格を探索するロジック
- `src/app/api/forecast/route.ts` — 部屋タイプ／プラン別の日別価格予測API
- `src/app/api/portfolio/route.ts` — ホテル全体（94室）のRevPAR予測API
- `src/app/page.tsx` — ダッシュボードUI

## 価格ロジックの考え方（RevPAR最大化）

単純に「需要が高いから値上げする」のではなく、**価格を上げるほど稼働率は下がる**
というトレードオフを需要曲線としてモデル化し、収益（RevPAR = 価格 × 稼働率）を
最大化する価格を数値探索（グリッドサーチ）で選んでいます。

1. **需要指数（demandIndex）の算出**：以下の要因を基準価格時点の稼働率への
   加減点として合成します。
   - 季節・曜日・祝日（週末/連休は上振れ）
   - 競合ホテルの価格動向（周辺相場が高ければ需要も強いとみなす）
   - 近隣イベント（展示会・花火大会・コンサート等の集客規模）
   - 天候予測（晴天は上振れ、荒天は下振れ）
   - 景気・為替（円安・消費者信頼感はインバウンド需要に影響）
   - 近隣地域の稼働率・検索需要
2. **価格感度（priceSensitivity）の算出**：予約リードタイム・イベントの有無・
   週末/祝日かどうかから、その日の「値上げへの許容度（需要の価格弾力性）」を
   算出します。直前予約や高需要日は感度が低く（強気の価格が有効）、
   早期予約の平日は感度が高く（値下げで稼働を稼ぐ方が有利）なります。
3. **需要曲線**：`occupancy(P) = 基準稼働率 × demandIndex × exp(-priceSensitivity × (P - 基準価格) / 基準価格)`
   という指数関数で、価格Pに対する稼働率を予測します。
4. **RevPAR最大化**：許容価格帯（`minPrice`〜`maxPrice`）を細かく区切って
   `価格 × 稼働率` を総当たりで計算し、最大となる価格を採用します
   （`optimizeForRevPar()`）。
5. 最後にプランごとの倍率（朝食付き・早期割引など）を掛けて表示価格にします。

`src/lib/pricingEngine.ts` の `recommendPrice()` は、算出した価格が
基準価格で売った場合よりどれだけRevPARを改善するか（`revParUplift`）、
なぜその価格が合理的かを説明する自然文（`rationale`）も返します。
`recommendPortfolioForDate()` は、各部屋タイプの最適価格を室数で加重平均し、
94室全体としてのRevPAR・稼働率・客室収入を算出します。

## 実運用のために：実データへの接続

現在 `src/lib/signals.ts` の各関数はデモ用の疑似乱数データを返しています。
実際に稼働させる際は、以下のような外部APIに置き換えてください（関数のインターフェースは
変えずに中身だけ差し替えれば、価格エンジン側の変更は不要です）。

| シグナル | 差し替え候補 |
| --- | --- |
| 競合価格 (`getCompetitorSignal`) | OTA価格比較サービス（RateGain, OTA Insight 等）やOTAサイトのレート取得API |
| イベント情報 (`getEventSignal`) | Ticketmaster API, ぴあ/イベント系API, 自治体・コンベンションセンターの公開カレンダー |
| 天候 (`getWeatherSignal`) | 気象庁（JMA）API, OpenWeatherMap API |
| 景気・為替 (`getEconomicSignal`) | e-Stat（景気動向指数）, 為替レートAPI |
| 地域需要 (`getAreaSignal`) | Google Popular Times相当のデータ, 自社PMSの周辺エリア稼働実績 |

また、`src/data/hotel.ts` を実際の部屋タイプ・プラン・料金レンジに置き換え、
PMS（宿泊管理システム）と連携して実際の在庫・過去実績（ピックアップ状況）を
`pricingEngine.ts` に組み込むことで、より精度の高いレベニューマネジメントが可能になります。
