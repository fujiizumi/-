# ホテル レベニューマネジメント AI

競合ホテルの価格、近隣イベント、天候、景気動向、地域の需要状況などを分析し、
**RevPAR（販売可能な客室1室あたり収益 = ADR × 稼働率）が最大になる価格**を
部屋タイプ・宿泊プランごとに日別で自動算出するダッシュボードです。全94室の
在庫を前提にしています。

## 使い方

```bash
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開くと、部屋タイプ・プラン・表示日数を選び、
日別の推奨価格・稼働予測・RevPARを確認できます。各行をクリックすると、
「なぜこの価格が合理的か」という根拠の説明文と、要因ごとの内訳
（競合価格、イベント、天候、景気、地域需要、価格感度）が展開されます。
ページ上部には、94室全体を対象にした期間平均RevPARと、基準価格で固定販売した
場合との収益比較（ホテル全体のRevPAR改善率）も表示されます。

## 構成

- `src/data/hotel.ts` — 部屋タイプ（合計94室）・プランのマスタデータ（実際のホテル情報に置き換えてください）
- `src/lib/signals.ts` — 外部要因シグナルの取得（**現在はデモ用の疑似データ**）
- `src/lib/pricingEngine.ts` — 需要曲線を推定し、RevPARを最大化する価格を探索するロジック
- `src/app/api/forecast/route.ts` — 部屋タイプ／プラン別の日別価格予測API
- `src/app/api/portfolio/route.ts` — ホテル全体（94室）のRevPAR予測API
- `src/app/page.tsx` — ダッシュボードUI

## 価格ロジックの考え方（RevPAR最大化）

単純に「需要が高いから値上げする」のではなく、**価格を上げるほど稼働率は下がる**
というトレードオフを需要曲線としてモデル化し、収益（RevPAR = 価格 × 稼働率）を
最大化する価格を数値探索（グリッドサーチ）で選んでいます。

1. **需要指数（demandIndex）の算出**：以下の要因を基準価格時点の稼働率への
   加減点として合成します。
   - 季節・曜日・祝日（週末/連休は上振れ）
   - 競合ホテルの価格動向（周辺相場が高ければ需要も強いとみなす）
   - 近隣イベント（展示会・花火大会・コンサート等の集客規模）
   - 天候予測（晴天は上振れ、荒天は下振れ）
   - 景気・為替（円安・消費者信頼感はインバウンド需要に影響）
   - 近隣地域の稼働率・検索需要
2. **価格感度（priceSensitivity）の算出**：予約リードタイム・イベントの有無・
   週末/祝日かどうかから、その日の「値上げへの許容度（需要の価格弾力性）」を
   算出します。直前予約や高需要日は感度が低く（強気の価格が有効）、
   早期予約の平日は感度が高く（値下げで稼働を稼ぐ方が有利）なります。
3. **需要曲線**：`occupancy(P) = 基準稼働率 × demandIndex × exp(-priceSensitivity × (P - 基準価格) / 基準価格)`
   という指数関数で、価格Pに対する稼働率を予測します。
4. **RevPAR最大化**：許容価格帯（`minPrice`〜`maxPrice`）を細かく区切って
   `価格 × 稼働率` を総当たりで計算し、最大となる価格を採用します
   （`optimizeForRevPar()`）。
5. 最後にプランごとの倍率（朝食付き・早期割引など）を掛けて表示価格にします。

`src/lib/pricingEngine.ts` の `recommendPrice()` は、算出した価格が
基準価格で売った場合よりどれだけRevPARを改善するか（`revParUplift`）、
なぜその価格が合理的かを説明する自然文（`rationale`）も返します。
`recommendPortfolioForDate()` は、各部屋タイプの最適価格を室数で加重平均し、
94室全体としてのRevPAR・稼働率・客室収入を算出します。

## 実運用のために：実データへの接続

現在 `src/lib/signals.ts` の各関数はデモ用の疑似乱数データを返しています。
実際に稼働させる際は、以下のような外部APIに置き換えてください（関数のインターフェースは
変えずに中身だけ差し替えれば、価格エンジン側の変更は不要です）。

| シグナル | 差し替え候補 |
| --- | --- |
| 競合価格 (`getCompetitorSignal`) | OTA価格比較サービス（RateGain, OTA Insight 等）やOTAサイトのレート取得API |
| イベント情報 (`getEventSignal`) | Ticketmaster API, ぴあ/イベント系API, 自治体・コンベンションセンターの公開カレンダー |
| 天候 (`getWeatherSignal`) | 気象庁（JMA）API, OpenWeatherMap API |
| 景気・為替 (`getEconomicSignal`) | e-Stat（景気動向指数）, 為替レートAPI |
| 地域需要 (`getAreaSignal`) | Google Popular Times相当のデータ, 自社PMSの周辺エリア稼働実績 |

また、`src/data/hotel.ts` を実際の部屋タイプ・プラン・料金レンジに置き換え、
PMS（宿泊管理システム）と連携して実際の在庫・過去実績（ピックアップ状況）を
`pricingEngine.ts` に組み込むことで、より精度の高いレベニューマネジメントが可能になります。

# 新規ホテル 収支シミュレーター（`/simulator`）

賃貸方式またはMC（マネジメントコントラクト）方式で新規ホテルを運営した場合に、
**1ホテルあたり年間営業利益1,500万円以上**（目標額は変更可）を出せるかを試算する画面です。
`npm run dev` 後、`http://localhost:3000/simulator` を開いてください。

- **売上**：客室数・稼働率・客室単価（ADR）・1室あたり人数から、客単価・RevPAR・TRevPAR・朝食/付帯売上を算出
- **売上原価**：朝食原価、付帯原価、OTA手数料（OTA比率×手数料率）、決済手数料
- **人件費**：正社員（人数・月給・賞与月数・交通費）、パート（人数・時給・1日労働時間・月勤務日数・交通費）、
  販売室数に連動する客室清掃（1室あたり清掃時間×時給、または外注単価）、法定福利費（正社員／パート別の率）
- **経費**：水道光熱費（変動＋基本料）、備品消耗品・アメニティ、洗濯リネン費、通信・システム、修繕、広告、その他
- **賃貸方式**：固定賃料＋変動賃料、保険料、開業投資の減価償却 → 自社営業利益
- **MC方式**：ベースフィー（売上比）＋インセンティブフィー（GOP比）−自社負担コスト → 運営会社の営業利益（オーナー利益も表示）
- 目標達成に必要な稼働率・ADR・RevPAR、損益分岐稼働率、稼働率×ADRの感応度表、賃貸/MCの比較
- 入力内容の自動保存、シナリオ保存、CSV出力、印刷

計算ロジックは `src/lib/profitSimulator.ts`（純粋関数）にまとまっています。初期値は地方都市・100室の宿泊特化型ホテルを想定した仮の数値です。

# 多店舗展開プランナー（`/portfolio`）と競合価格の自動取得

画面上部のナビから「多店舗展開」「収支シミュレーター」「価格ダッシュボード」を切り替えられます。

## エリア・客室数の選択（収支シミュレーター）

- 全国17エリア（札幌〜那覇・地方都市）から出店エリアを選び、客室数（50〜250室のプリセットまたは任意）を選ぶと、
  ADR・稼働率・時給（最低賃金ベース）・人員配置・賃料・固定費をエリアと規模に合わせた標準値に置き換えます。
- エリアの標準値は `src/data/areas.ts` にあります。**社内検討用の仮の目安**なので、自社の実績・物件条件・最新の最低賃金で更新してください。

## 周辺競合ホテルの価格自動取得

収支シミュレーターの「周辺競合ホテルの価格比較」で、物件の緯度・経度から半径0.5〜3km以内で販売中のホテルの
**1名1室・最安プラン料金（税込）**を、平日と休前日の2日分取得します。中央値から相場ADR（税抜換算）を出し、
自社ADRとの差を表示します。「自社ADRに反映」ボタンで相場の○%をADRに設定できます。

取得には楽天ウェブサービスのアプリID（無料）が必要です。

1. https://webservice.rakuten.co.jp/ でアプリIDを発行する
2. プロジェクト直下に `.env.local` を作り、次の内容を書く

   ```
   RAKUTEN_APP_ID=発行されたアプリID
   # 楽天側で接続先や認証方式が変わった場合のみ設定
   # RAKUTEN_TRAVEL_ENDPOINT=https://app.rakuten.co.jp/services/api/Travel/VacantHotelSearch/20170426
   # RAKUTEN_ACCESS_KEY=...
   ```

3. `npm run dev` を再起動する

アプリIDが未設定の場合や、APIがエラーを返した場合は**デモデータ**を表示します（画面に「▲ デモデータ」と表示されます）。
取得結果はサーバー側で1時間キャッシュします。実装は `src/lib/competitors.ts` と `src/app/api/competitors/route.ts` です。

## 多店舗展開プランナー

- 収支シミュレーターで「多店舗計画に保存」した店舗を一覧で管理（ステータス：候補／交渉中／契約済／開業済、開業予定月）
- 全社KPI：店舗数・総客室数・売上合計・店舗利益合計・本部経費・全社営業利益・目標達成店舗数・開業投資合計・回収見込み年
- 年度別の全社収支予測：開業月から計上し、開業1年目・2年目は稼働率に係数（初期値85%・95%）をかけ、本部経費・開業投資・累計キャッシュフローを表示
- 次の出店エリア比較：同じ客室数・方式で全エリアを試算してランキングし、1店舗あたり目標利益を達成するのに必要な最小の客室数を表示
- CSV出力、計画のJSON書き出し・読み込み（チームでの共有用）。データはブラウザの localStorage に保存されます

# スマホからも使える公開版（単一HTML）

`npm run build:standalone` で、収支シミュレーターと多店舗展開プランナーを、サーバー不要の1枚のHTML
（`dist/hotel-expansion.html`）にまとめます。claude.ai のアーティファクトなどに置けば、スマホのブラウザから開けます。

公開版の制限：
- 外部サイトに接続できないため、競合価格の自動取得はデモデータになります。実際の価格は「競合の料金を手入力する」で登録できます。
- ファイルの保存ができないため、CSV・JSONの出力は「内容をコピー」する画面になります。読み込みは貼り付けでも行えます。
- 価格ダッシュボード（`/`）はサーバーのAPIを使うため、公開版には含まれません。
- データは開いたブラウザごとに保存されます（スマホとPCでは別々）。共有は書き出し／読み込みで行ってください。

# 損益分岐点分析

収支シミュレーターの「損益分岐点分析」に、損益分岐点売上高（年・月）、目標利益達成売上高、安全余裕率、
損益分岐点稼働率、固定費・変動費率・限界利益率・損益分岐点比率と、損益分岐点図表を表示します。

- 賃貸方式：稼働率0%と100%の試算から固定費と変動費率を求め、`損益分岐点売上高 = 固定費 ÷ 限界利益率`（ADR・客単価は現在の入力のまま）
- MC方式：運営会社の利益はフィー体系により売上に対して折れ線になるため、利益が0になる売上高を数値計算。オーナー側の損益分岐点売上高も表示
- 多店舗展開プランナーの店舗一覧・CSVにも、損益分岐点売上高と安全余裕率を表示します

# 月別試算（季節変動）

収支シミュレーターの「月別試算」で、1〜12月の稼働率・ADR・売上高・GOP・営業利益・累計営業利益を表示します。

- 季節パターン（`src/data/seasonality.ts`）：季節変動なし／都市型／北海道都市型／道北・夏季集中型（稚内など）／観光都市（春・秋ピーク）／リゾート（沖縄）。
  エリアを選ぶと、そのエリアに合ったパターンが自動で入ります。「季節指数を編集」で月ごとの指数（100 = 年平均）を変更できます
- 年平均の稼働率（日数加重）とADR（販売室数加重）が入力値と一致するよう指数を自動調整するので、12か月の合計は年間試算と一致します
- 固定費（正社員給与・固定シフトのパート・賃料など）は毎月同額、賞与は12か月で按分、変動費は各月の販売室数に比例
- 赤字の月、最も利益の出る月・厳しい月、1月からの累計営業利益の最大落ち込み（運転資金の目安）を表示
- 多店舗展開プランナーの年度別予測も、開業月と季節変動を反映した月別試算の積み上げで計算します
